如何启用 GitHub Pages

INTERACTIVE TUTORIAL · 把网页发布成公网网址

上一篇讲完了 Git 和 GitHub 的基础，这一篇教你把自己的网页「发布上线」—— 用 GitHub Pages 免费得到一个 你的用户名.github.io/仓库名/ 这样的公网网址。 跟着下面的步骤点一遍，再试试网址生成器，你就懂了。

先满足三个前提

1仓库是 Public

免费账户下，GitHub Pages 只能用于公开仓库。私有仓库要 Pro 才支持 Pages。

2网页文件已推送

仓库里要有 index.html（或 README 自动生成页），并已经 push 到 GitHub。

3记住两个名字

你的用户名、仓库名。网址格式由它们决定，见下方的网址生成器。

六步操作

在 GitHub 网页上点几下就能完成，不需要命令行。

1

打开仓库的 Settings

进入你的仓库页面，点顶部右侧的 Settings 标签。

2

找到 Pages

左侧边栏往下滚，在 Code and automation 分组里点 Pages。

3

选择发布来源

Source 下拉选 Deploy from a branch（从分支部署）。

4

选分支和目录

Branch 选 main，目录选 / (root)（网页在根目录）或 /docs（网页在 docs 文件夹）。

把 index.html 放在仓库根目录，这里就选 / (root)。

5

点 Save

保存后，GitHub 会自动开始构建部署。

6

等待并访问

首次构建通常要 1～2 分钟。完成后页面会显示你的网址，浏览器打开即可。

网址生成器

填上你的用户名和仓库名，下面会实时生成你的 Pages 网址。

https://你的用户名.github.io/你的仓库名/

几个注意事项

⚠ 首次要等一会

第一次构建通常 1～2 分钟，之后每次 push 会自动重新构建，几十秒内生效。别急着刷新以为坏了。

网址是固定的

格式永远是 用户名.github.io/仓库名/，一个用户一个用户名主页，无法自定义子路径。

支持自定义域名

有自己的域名？可以在 Pages 设置里绑定，再按提示配置 CNAME 即可。

只适合静态网页

Pages 只能托管静态内容（HTML/CSS/JS），不能跑后端、数据库或服务端程序。

小测验

点选答案，立刻知道对错。

1. 免费账户下，GitHub Pages 可以用于哪种仓库？

2. 网页文件放在仓库根目录，发布目录应该选？

3. 用户名 user、仓库名 my-site，Pages 网址是？
